## 1. 设计原则与通用约定

| 项 | 约定 |
| --- | --- |
| 基础路径 | `/api/v1` |
| 协议 | HTTP/1.1（SSE 用 `text/event-stream`），生产建议 HTTPS |
| 数据格式 | JSON（`application/json; charset=utf-8`），SSE 事件为 `text/event-stream` |
| 命名风格 | 字段 `snake_case`，与 Python/Pydantic 一致 |
| 时间格式 | ISO 8601 UTC，如 `2026-09-30T08:00:00Z` |
| 认证 | MVP 内网可省略；预留 `Authorization: Bearer <token>`（v1.3 落地） |
| 追踪 | 请求头 `X-Trace-Id`（缺省由服务端生成），贯穿 LangSmith/日志 |
| 幂等 | 写操作接口支持 `Idempotency-Key` 请求头（发送、审核） |
| 版本策略 | 路径带版本号；破坏性变更升 `v2`，字段新增视为兼容 |

### 1.1 统一响应封装（非流式接口）

```json
{
  "code": 0,
  "message": "ok",
  "trace_id": "b1c2d3e4",
  "data": {}
}
```

- `code = 0` 表示成功；非 0 为业务错误（见 §6）。
- SSE 接口不套此封装，改用事件（见 §5）。

## 2. 通用数据模型（Schema）

### 2.1 枚举定义

| 枚举 | 取值 |
| --- | --- |
| `Intent` | `consult`（咨询）、`sensitive`（敏感/复杂） |
| `Source` | `employee`（员工）、`customer`（客户） |
| `ReviewStatus` | `pending`、`approved`、`rejected` |
| `SendStatus` | `pending`、`sent`、`failed` |
| `TicketStatus` | `processing`、`awaiting_review`、`sent`、`rejected`、`failed` |
| `DocSource` | `manual`、`faq`、`ticket` |
| `RetrievalMode` | `hybrid`、`dense_only`、`sparse_only`、`degraded` |

### 2.2 `Message`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `role` | string | 是 | `user` / `assistant` / `reviewer` |
| `content` | string | 是 | 消息内容 |
| `created_at` | string | 否 | ISO 8601 |

### 2.3 `Chunk`（检索结果片段）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `chunk_id` | string | 是 | 片段唯一标识（`doc_id#n`） |
| `doc_id` | string | 是 | 文档标识 |
| `content` | string | 是 | 片段文本 |
| `source` | `DocSource` | 是 | 来源类型 |
| `title` | string | 否 | 标题/问题 |
| `version` | string | 否 | 版本号 |
| `error_code` | string | 否 | 错误码 |
| `dense_score` | number | 否 | 稠密通道分数 |
| `sparse_score` | number | 否 | 稀疏通道分数 |
| `rrf_score` | number | 否 | 融合分数 |
| `rerank_score` | number | 否 | 重排分数（未启用则空） |
| `rank` | integer | 否 | 最终排名 |

### 2.4 `Ticket`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `ticket_id` | string | 是 | 工单标识（客户端生成或服务端返回） |
| `session_id` | string | 是 | 会话标识 |
| `query` | string | 是 | 用户问题 |
| `source` | `Source` | 否 | 提交来源，默认 `employee` |
| `intent` | `Intent` | 否 | 意图识别结果 |
| `status` | `TicketStatus` | 否 | 工单状态 |
| `draft` | string | 否 | 草稿内容 |
| `reply` | string | 否 | 最终回复 |
| `citations` | string[] | 否 | 引用片段 id 列表 |
| `created_at` | string | 否 | 创建时间 |
| `updated_at` | string | 否 | 更新时间 |

### 2.5 `ReviewPayload`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `ticket_id` | string | 是 | 工单标识 |
| `session_id` | string | 是 | 会话标识 |
| `decision` | string | 是 | `approved` / `rejected` |
| `comment` | string | 否 | 审核意见 |
| `edited_reply` | string | 否 | 人工修改后的最终文案（优先使用） |

### 2.6 `Error`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | integer | 业务错误码（§6） |
| `message` | string | 可读错误信息 |
| `detail` | object | 可选，调试信息（生产可关闭） |
| `trace_id` | string | 追踪 id |

## 4. 接口详细定义

### 4.1 `POST /api/v1/ticket/query`（SSE）

**请求头**

| 头 | 必填 | 说明 |
| --- | --- | --- |
| `Content-Type` | 是 | `application/json` |
| `Accept` | 是 | `text/event-stream` |
| `X-Trace-Id` | 否 | 追踪 id |

**请求体**

```json
{
  "ticket_id": "T-1001",
  "session_id": "S-abc",
  "query": "升级到 v1.2.3 后登录报错 ERR-4041，怎么办？",
  "source": "employee",
  "history": [
    { "role": "user", "content": "我升级了版本" },
    { "role": "assistant", "content": "请问具体报错是什么？" }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `ticket_id` | string | 是 | 工单标识 |
| `session_id` | string | 是 | 会话标识（多轮需一致） |
| `query` | string | 是 | 问题正文，长度 1~4000 |
| `source` | `Source` | 否 | 默认 `employee` |
| `history` | `Message[]` | 否 | 多轮历史（MVP 可为空） |

**响应**：`text/event-stream`，事件见 §5。

**示例（cURL）**

```bash
curl -N -X POST http://localhost:8000/api/v1/ticket/query \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{"ticket_id":"T-1001","session_id":"S-abc","query":"ERR-4041 怎么解决？"}'
```

**请求体**：见 §2.5 `ReviewPayload`


**错误场景**：工单不存在（`1004`）、非待审核状态（`1005`）、会话已过期（`1006`）。

## 5. SSE 事件契约

每个事件形如：

```
event: <type>
id: <seq>
data: <json>

```

| event | data 字段 | 时机 | 说明 |
| --- | --- | --- | --- |
| `start` | `{ticket_id, session_id}` | 连接建立 | 首事件 |
| `intent` | `{intent, need_review}` | 意图识别完成 | — |
| `retrieval` | `{mode, hit_count, top_docs[]}` | 检索完成 | 可脱敏，`top_docs` 为精简 Chunk |
| `token` | `{delta}` | 草稿生成中 | 逐 token 推送 |
| `draft` | `{draft, citations[]}` | 草稿完成 | — |
| `review_required` | `{ticket_id, reason}` | 触发人工审核 | 之后流结束，等待审核接口 |
| `done` | `{reply, send_status, citations[]}` | 流程正常结束 | — |
| `error` | `{code, message}` | 任意阶段异常 | 之后流结束 |
| `ping` | `{}` | 心跳（可选） | 保持连接 |

**示例流**

```
event: start
data: {"ticket_id":"T-1001","session_id":"S-abc"}

event: intent
data: {"intent":"sensitive","need_review":true}

event: retrieval
data: {"mode":"hybrid","hit_count":5,"top_docs":[{"chunk_id":"manual-01#3","title":"登录模块 FAQ"}]}

event: token
data: {"delta":"请"}

event: token
data: {"delta":"确认"}

event: draft
data: {"draft":"请确认版本……","citations":["manual-01#3"]}

event: review_required
data: {"ticket_id":"T-1001","reason":"命中敏感关键词"}

```

> 客户端约定：收到 `review_required` 或 `error` / `done` 即可关闭连接。断线重连建议携带 `Last-Event-ID`（v1.1）。

## 6. 错误码表

| code | HTTP | 含义 | 处理建议 |
| --- | --- | --- | --- |
| 0 | 200 | 成功 | — |
| 1001 | 400 | 参数校验失败 | 检查请求体 |
| 1002 | 401 | 未认证（预留） | 补充 Token |
| 1003 | 403 | 无权限（预留） | — |
| 1004 | 404 | 工单/会话不存在 | 确认 id |
| 1005 | 409 | 状态不合法（如非待审核却提交审核） | 查询状态后重试 |
| 1006 | 410 | 会话已过期 | 新建会话 |
| 2001 | 502 | 向量服务（Milvus）不可用 | 触发降级或转人工 |
| 2002 | 502 | 生成服务（Ollama）不可用 | 重试 / 转人工 |
| 2003 | 504 | 检索/生成超时 | 重试 |
| 2004 | 500 | 编排节点内部错误 | 查看 `trace_id` |
| 3001 | 429 | 触发限流 | 退避重试 |
| 9000 | 500 | 未知错误 | 上报 |

## 7. 数据契约一致性要求

- 所有 Schema 以 Pydantic 模型为唯一事实来源（single source of truth），OpenAPI 由 FastAPI 自动生成。
- SSE 事件的 `data` 结构同样定义 Pydantic 模型，避免前后端结构漂移。
- 状态枚举（§2.1）在数据库、API、编排 State 三处保持一致，不得各自定义。
- `TicketState`（编排内部）与 API Schema 之间通过显式映射函数转换，不直接暴露内部结构。

## 8. 前后端交互时序

```
前端                      API                    编排(LangGraph)
 │  POST /ticket/query ──► │                          │
 │ ◄── event: start ───────│                          │
 │ ◄── event: intent ──────│ ◄── intent_node ─────────│
 │ ◄── event: retrieval ───│ ◄── retrieve_node ───────│
 │ ◄── event: token ×N ────│ ◄── draft_node(流式) ────│
 │ ◄── event: review_required ── interrupt 触发 ──────│
 │                         │                          │
 │  (人工在客服台审核)      │                          │
 │  POST /ticket/review ──►│ ── Command(resume) ─────►│
 │ ◄── data:{send_status} ─│ ◄── finalize/send_node ──│
```
