## 1. 架构目标与设计原则

| 原则 | 说明 |
| --- | --- |
| 分层解耦 | 接入 / 编排 / 检索 / 生成 / 评估 各层职责单一，接口清晰，便于替换模型与组件 |
| 本地可控 | 生成与向量化使用本地模型（Ollama），不依赖外部大模型 API，算力与数据可控 |
| 混合检索优先 | 稀疏（BM25）+ 稠密（向量）并行，RRF 融合 + 重排，兼顾专有名词与语义提问 |
| 人在回路 | 敏感/复杂工单强制人工审核，编排层原生支持挂起与恢复 |
| 可观测可评估 | 全链路追踪（LangSmith）+ 离线评估（RAGAS），效果可量化、可回归 |
| 配置与密钥分离 | 通过环境变量注入，便于 Docker 部署与多环境切换 |

## 3. 核心数据流

1. **接入**：客户端提交工单 → FastAPI 接收 → 建立 SSE 通道。
2. **意图识别**：LangGraph 首个节点分类意图（咨询 / 故障 / 投诉 / 敏感）。
3. **检索**：查询同时走 稠密向量检索 与 BM25 稀疏检索 → RRF 融合 → Qwen3-Reranker 重排 → 取 Top-K 上下文。
4. **生成**：Qwen2.5 基于上下文流式生成草稿 → 通过 SSE 边生成边回传。
5. **审核分支**：
   - 普通工单：草稿直接返回，等待人工确认或自动发送；
   - 敏感/复杂工单：`interrupt` 挂起，持久化状态，等待人工审核接口回调。
6. **发送**：审核通过后恢复图执行，发送回复并落库。
7. **多轮**：同 session 的后续追问从 Checkpointer 恢复上下文。
8. **观测**：全链路 trace 上报 LangSmith；离线用 RAGAS 评估。

## 4. 技术选型明细

| 环节 | 选型 | 理由 | 备选 / 对比 |
| --- | --- | --- | --- |
| 接口框架 | **FastAPI** | 异步原生、自动 OpenAPI 文档、SSE 支持好 | Flask（同步弱）、Django（偏重） |
| 流式协议 | **SSE** | 单向流式简单可靠，浏览器原生支持 | WebSocket（双向，此处不需要） |
| 编排引擎 | **LangGraph** | 图状态机、原生 Checkpointer + interrupt，适配人在回路 | LangChain 顺序链（无中断/恢复能力） |
| 组件库 | **LangChain** | Tools / Memory / Middleware 生态成熟，与 LangGraph 无缝 | 原生手写（重复造轮子） |
| 生成模型 | **Qwen2.5（Ollama）** | 本地部署、中文强、算力可控、数据不出内网 | GPT/Claude（外部 API，数据合规差） |
| 向量化 | **qwen3-embedding** | 中文语义强，与 Qwen 系一致 | BGE / m3e（亦可，视效果对比） |
| 向量库 | **Milvus** | 原生内置 BM25、支持稠密+稀疏混合、可扩展 | FAISS（无服务化/BM25）、pgvector（混合能力弱） |
| 稀疏检索 | **Milvus 内置 BM25** | 与向量库同源，免额外 ES，专有名词/错误码命中率高 | Elasticsearch（运维成本高） |
| 融合 | **RRF** | 无需调权重、鲁棒，适合异构分数融合 | 加权求和（需调参、分数不归一） |
| 重排 | **Qwen3-Reranker** | 精排提升 Top-K 精度，语义一致 | BGE-Reranker（可选对比） |
| 评估 | **RAGAS 六指标** | 面向 RAG 的标准指标，可离线回归 | 人工评测（成本高、不可回归） |
| 可观测 | **LangSmith** | 全链路 trace / 调试 / 数据集评估，与 LangChain 原生集成 | Langfuse（可选替代） |
| 部署 | **Docker + docker-compose** | 一键拉起多服务（API/Milvus/Ollama），环境一致 | 裸机部署（环境漂移） |

### 4.1 RAGAS 六指标（评估口径）

| 指标 | 含义 |
| --- | --- |
| Faithfulness | 回答是否忠实于检索上下文（无幻觉） |
| Answer Relevancy | 回答与问题的相关程度 |
| Context Precision | 检索上下文的精确率（相关文档排位） |
| Context Recall | 检索上下文的召回率（覆盖标准答案） |
| Answer Correctness | 回答与标准答案的一致度 |
| Context Entities Recall | 关键实体（错误码/版本号等）召回情况 |

## 5. 关键设计决策（ADR 摘要）

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| ADR-01 | 采用混合检索而非单一向量检索 | 知识库含大量专有名词/错误码/版本号，纯语义易漂移；BM25 保底 + RRF 融合 |
| ADR-02 | 生成与向量化全部本地化 | 数据合规、算力可控，避免外部 API 依赖 |
| ADR-03 | LangGraph 而非线性链 | 需要人工审核中断/恢复与多轮状态，图 + Checkpointer 天然适配 |
| ADR-04 | 敏感工单强制 interrupt | 合规要求，宁可多一次人工审核，不可误发 |
| ADR-05 | 评估与线上解耦 | RAGAS 离线跑评估集，LangSmith 负责线上追踪，互不阻塞 |

## 8. 技术风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 本地模型算力不足 | 生成/向量化延迟高 | 选用合适参数量（如 7B）、量化、GPU 优先、流式输出降低体感延迟 |
| Milvus 部署复杂 | 环境搭建成本 | docker-compose 编排 etcd/minio，提供一键脚本 |
| 重排增加延迟 | 首字延迟上升 | 重排限定 Top-N（如 50→5），与流式生成并行编排 |
| Checkpointer 状态膨胀 | 存储增长 | 定期归档/清理过期会话，设置 TTL |
| LangSmith 数据外发 | 合规顾虑 | 仅上报必要元数据，敏感字段脱敏；必要时切换自托管 Langfuse |
| 评估集缺失 | 无法量化效果 | 尽早构建标注评估集，作为 CI 回归门槛 |
