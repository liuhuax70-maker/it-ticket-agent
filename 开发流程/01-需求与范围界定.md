# 需求与范围界定

> 项目名称：企业内部 IT/客服工单智能处理助手
> 文档版本：v1.0
> 文档状态：已确认
> 更新日期：2026-09-30

---

## 1. 项目背景

企业内部员工或外部客户在遇到 IT 系统、产品使用问题时，会提交工单。人工客服/IT 支持人员需要：

- 从产品手册、FAQ、历史工单等内部知识库中查找答案；
- 撰写回复草稿；
- 对复杂或敏感工单进行人工审核后再发送。

该过程重复性高、知识查找耗时、回复质量依赖个人经验，因此需要一套 **智能工单处理助手**，实现「自动检索知识库 → 生成回复草稿 → 人工审核 → 发送」的半自动闭环。

## 2. 项目目标

| 目标 | 说明 | 衡量方式 |
| --- | --- | --- |
| 提升响应效率 | 自动生成回复草稿，减少人工查找与编写时间 | 单工单平均处理时长下降 |
| 提升回复质量 | 基于内部知识库生成，引用可追溯 | RAGAS 六指标达标 |
| 保证合规安全 | 复杂/敏感工单必须人工审核后发送 | 审核拦截率、误发率 |
| 效果可评估 | 线上效果可追踪、可回归 | LangSmith 全链路追踪覆盖 |

## 3. 业务范围

### 3.1 范围内（In Scope）

1. **工单接入**：接收员工/客户提交的 IT/产品问题工单。
2. **意图识别**：对用户提问进行意图分类（咨询 / 故障 / 投诉 / 敏感等）。
3. **知识检索**：混合检索内部知识库（产品手册、FAQ、历史工单）。
4. **草稿生成**：基于检索结果生成回复草稿。
5. **人工审核**：复杂或敏感工单转人工审核、可修改后确认。
6. **回复发送**：审核通过后发送回复。
7. **多轮追问**：支持在同一会话中继续追问（会话状态可恢复）。
8. **效果评估与追踪**：RAGAS 评估、LangSmith 观测。

### 3.2 范围外（Out of Scope）

- 知识库内容的原始生产与维护流程（仅做接入与检索）。
- 工单系统本身的 UI 重构（仅提供 API 对接）。
- 非 IT/客服类业务的通用问答。
- 多租户权限体系（本期仅单体企业内部使用）。

## 4. 功能需求

### FR-1 工单接入与流式响应
- 提供 HTTP 接口接收工单，支持 **SSE 流式**返回生成内容。
- 接口层使用 **FastAPI**。

### FR-2 意图识别
- 判断工单意图类别，用于路由后续流程。
- 识别结果决定是否进入人工审核分支。

### FR-3 混合检索
- 支持 **BM25 稀疏检索**（专有名词、错误码、版本号）与 **稠密向量检索**（语义化提问）并行。
- 使用 **RRF** 融合两路结果，再用 **Qwen3-Reranker** 重排。
- 向量库采用 **Milvus**（内置 BM25），embedding 采用 **qwen3-embedding**。

### FR-4 草稿生成
- 基于检索上下文生成回复草稿。
- 生成模型采用 **Qwen2.5**（本地 **Ollama** 部署）。

### FR-5 人工审核（Human-in-the-loop）
- 复杂或敏感工单触发中断，转人工审核。
- 使用 **LangGraph Checkpointer + interrupt** 实现会话挂起与恢复。

### FR-6 多轮追问与会话记忆
- 支持多轮追问，保留会话状态。
- 使用 **LangChain Memory** 与 Checkpointer 持久化。

### FR-7 发送
- 审核通过后发送回复。
- 发送前完成最终状态校验。

### FR-8 可观测与评估
- 全链路追踪：**LangSmith**。
- 效果评估：**RAGAS 六指标**。

## 5. 技术栈映射

| 环节 | 技术选型 |
| --- | --- |
| 接口 | FastAPI + SSE 流式 |
| 编排 | LangGraph（意图识别 → 检索 → 草稿 → 人工审核 → 发送） |
| 组件 | LangChain（Tools / Memory / Middleware） |
| 生成 | Qwen2.5（Ollama） |
| 检索 | qwen3-embedding + Milvus 内置 BM25 + RRF + Qwen3-Reranker |
| 评估 | RAGAS 六指标 |
| 可观测 | LangSmith |
| 部署 | Docker + docker-compose |

## 6. 核心流程（编排）

```
用户提交工单
      │
      ▼
[意图识别] ──敏感/复杂──► [人工审核] ──通过──► [发送]
      │                        ▲
   普通咨询                     │
      ▼                        │
[混合检索] ──► [草稿生成] ──────┘
   (BM25 + 向量 → RRF → Rerank)
```

- 编排由 **LangGraph** 承载，节点间状态通过 Checkpointer 持久化。
- 人工审核节点使用 **interrupt** 挂起，审核完成后恢复执行。

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 检索与草稿生成支持流式输出，首字延迟可控 |
| 算力 | 本地 Qwen2.5 + Ollama，算力要求可控，不依赖外部大模型 API |
| 可扩展 | 检索/生成/评估组件解耦，便于替换模型 |
| 可观测 | 关键链路节点均可被 LangSmith 追踪 |
| 可部署 | 提供 Docker + docker-compose 一键启动 |
| 可维护 | 配置与密钥分离（环境变量），模块边界清晰 |

## 8. 关键技术与风险

| 风险点 | 说明 | 应对 |
| --- | --- | --- |
| 专有名词检索不准 | 错误码/版本号语义漂移 | BM25 保底 + RRF 融合 |
| 语义提问召回差 | 纯关键词匹配不足 | 稠密向量 + Reranker |
| 敏感工单误发 | 合规风险 | 强制人工审核 interrupt |
| 多轮上下文丢失 | 会话状态管理复杂 | Checkpointer 持久化 |
| 效果不可量化 | 无法回归验证 | RAGAS 六指标基线 |

## 9. 交付物

1. FastAPI 服务（SSE 流式接口）。
2. LangGraph 编排图（含人工审核中断/恢复）。
3. Milvus 检索模块（BM25 + 向量 + RRF + Rerank）。
4. Qwen2.5（Ollama）生成模块。
5. RAGAS 评估脚本与报告。
6. LangSmith 追踪接入。
7. Docker + docker-compose 部署文件。

## 10. 验收标准（摘要）

- [ ] 工单可通过 SSE 流式返回草稿。
- [ ] 专有名词与语义提问两类查询均能正确召回。
- [ ] 敏感/复杂工单可正确触发人工审核并支持恢复发送。
- [ ] 多轮追问上下文可恢复。
- [ ] RAGAS 六指标达到约定基线。
- [ ] 全链路可在 LangSmith 中追踪。
- [ ] docker-compose 可一键启动全部服务。
