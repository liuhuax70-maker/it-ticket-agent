# ADR 0008：用实测标定的余弦相似度阈值判定「无相关结果」

- 状态：已采纳
- 日期：2026-10-08

## 背景

用户问「你好」，界面却列出一堆知识库切片（数据合规与留存制度之类）。
根因不是前端，而是**检索层无法表达「无相关结果」**：

混合检索用 RRF 融合，RRF 分数只反映**排名**、不反映**相关性**。
「你好」在 62 个分块里都能排到第 1（它和每段文本都有一点点余弦相似度），
于是 RRF 给它一个"看起来很高"的融合分，编排层据此认为"有资料"，
生成阶段再把无关切片挂成引用。

在此之前，系统对"答不出来"的处理是**拒答**，所以这个缺陷被掩盖了：
无关切片顶多让拒答来得快一点。改成「无资料时也作答」之后，它才暴露出来——
用户看到的是「你好」+ 一堆制度引用。

ADR 0003 当年就写过解法（"让检索阶段产出「无相关结果」……需要先有 eval set"），
但一直没有 eval set 就一直没做。这次先用 22 条实测样本标定阈值。

## 决策

引入 `min_score`，取值 **0.43**，作用在**向量路**（余弦相似度）。

标定数据（`mode=vector`，top1 分数）：

| 类别 | 条数 | 分数范围 | 均值 |
| --- | --- | --- | --- |
| 无关提问 | 10 | 0.3077 ~ 0.4077 | 0.3464 |
| 真实制度提问 | 12 | 0.4521 ~ 0.7785 | 0.6219 |

无关类别最高 0.4077，真实类别最低 0.4521，**中间是干净空档**。
0.43 距两侧各约 0.022，是这份语料 + bge-small-zh-v1.5 上的最优切点。

在 `hybrid.search` 里再加一道闸门：**向量路经阈值过滤后为空，则整体判为无相关**，
不再让 BM25 把结果"救"回来。理由是 BM25 只反映字面词面命中——
「你好」命中「数据合规与留存制度」不代表资料与问题相关。

## 关键约束：阈值必须随语料/模型重新标定

余弦相似度的**绝对值与分布随嵌入模型而变**。换模型后沿用 0.43 会出现两种静默故障：

- 模型分数整体偏高 → 阈值形同虚设，无关提问照样召回（回到本 ADR 要修的状态）
- 模型分数整体偏低 → 阈值变成静默误杀，真实问题被判无相关，用户只看到通用知识
  而**没有任何报错**

重新标定的方法（不依赖本仓库的测试）：

1. 收集 10~15 条**明确不该召回**的提问（寒暄、闲聊、通用编程、翻译）
2. 收集 20 条以上**必须召回**的真实制度提问
3. 对每条调 `POST /search`（`mode=vector`），记 top1 分数
4. 取「无关类别最高分」与「真实类别最低分」的中点，两侧余量尽量均衡
5. 核对 `false_refusal_rate` 与 `citation_coverage` 没有异常劣化再上线

## 代价与已知局限

1. **纯字面精确匹配可能落空**（如问某个工单号）。缓解：带引号的短查询会由
   `resolve_mode` 切到 keyword 单路，不受这条闸门约束。
2. **阈值偏低的语料上会欠召回**。本 ADR 的数值只对当前语料有效，换域必须重标。
3. **只约束向量路**。BM25 分数量纲是 5~9，与余弦相似度不同量纲，
   共用同一个 `min_score` 在 BM25 上是无效比较（永远不触发）——
   这一点原先只写在注释里，现在闸门逻辑依赖它，故在此显式记录。
4. 副作用是**跨租户/越权召回不受影响**：ACL 过滤在两路都生效，
   阈值闸门只判断相关性，不参与权限判断（见 ADR 0006）。
