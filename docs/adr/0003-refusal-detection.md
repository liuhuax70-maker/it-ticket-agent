# ADR 0003：拒答判定用「哨兵 + 话术 + 短句」三层，且拒答一律清空引用

- 状态：已采纳
- 日期：2026-10-07

## 背景

最小闭环验收有一条判据：问文档里没有的问题时，接口必须拒答、不能编造。

第一版实现只识别**固定拒答话术**：提示词里要求模型「原样回复：`抱歉，我没有……`」，
守卫节点判断 `REFUSE_TEXT in answer`。实测（本地 Qwen 4B/9B）暴露出三个问题：

1. 模型很少逐字复述话术，而是用自己的话说明：「公司年会的举办酒店在提供的参考资料中未提及。」——
   这是**正确行为**，却因为话术不匹配被当成正常作答；
2. 更糟的是它还给这种答案挂上了 `[1][2][3][4][5]` 引用，反而让用户以为有资料支撑；
3. 反过来，放宽成「出现『未提及』就算拒答」又会误判：
   「手册未提及加班费，但规定了年假……」是有实质内容的正常回答。

## 决策

拒答判定分三层，从最可靠到兜底：

| 层 | 判据 | 说明 |
| --- | --- | --- |
| 1 | 哨兵 `NO_ANSWER` | 提示词 v2 要求「完全无法回答时**只输出** `{{refuse_marker}}`」。机器可识别，不受措辞影响 |
| 2 | 固定话术 `REFUSE_TEXT` | 兼容 v1 提示词与模型自由复述 |
| 3 | 短句否定表述 | 兜底：命中「未提及 / 未包含 / 无法回答 / not mention…」**且**答案长度 ≤ 80 字 |

并且：

- **拒答一律清空 `citations`**，并把答案归一化为统一的 `REFUSE_TEXT`——
  对外话术必须一致，不能让模型的自由表述直接透给用户；
- 归一化时在 `errors` 里记 `refusal_detected`，便于观测「有多少请求走了拒答」。

## 理由

1. **可判定性优先**：让模型输出一个机器可识别的标记，比匹配自然语言可靠得多；
   自然语言判定永远在「漏判」和「误判」之间摇摆。
2. **引用与拒答互斥**：引用是置信声明，拒答是放弃声明，两者同时出现一定是错的。
3. **兜底层的长度约束**是刻意的：区分「说明某处没写」和「整篇答不出来」，
   最便宜且有效的信号是答案里还有没有别的实质内容。

## 代价与后续

- 兜底层仍是启发式，存在误判可能（例如「无法回答」出现在长答案中的合法场景，
  或长度恰好 80 字出头的拒答）。缓解方式是**优先依赖哨兵**，并在评测集里加入负样本回归。
- 更彻底的方案是让检索阶段产出「无相关结果」——即用评测集标定相关性阈值，
  使不可回答的问题在 `retrieve` 节点就返回空、走图上已有的 `refuse` 分支（不调用 LLM）。
  这需要先有 eval set，属于后续阶段（见 README「当前边界」）。

## 补记（2026-10-07）：兜底层按预期失效，根因在提示词规则，已用 v3 修复

换上 DeepSeek 并用扩充后的评测集（20 条应拒答样本）实测，**上面预判的两种误判都发生了**：

- `negative-10`（问美国加州的数据隐私法规，语料里只有本公司内部制度）与
  `negative-11`（问与字节跳动的绩效差异，语料里只有本公司薪酬制度）**未被判为拒答**，
  答案分别是"无法确认……参考资料仅涉及本公司制度[1][2][3]"、"无法比较……未包含字节跳动[4]"。
  两条都超过 80 字，故兜底层不生效——正是「长度恰好 80 字出头的拒答」那一类。
- 后果不止是指标虚高（误答率 20% 而非实际应有的 0%）：**引用没有被清空**，
  用户问语料外问题会拿到"无法确认"外加 5 条不相关制度的引用，看起来"有依据"。

根因不在兜底层，而在**提示词 v2 的规则本身**：

> v2 规则 2：「参考资料中只要包含与问题**相关**的内容，就**必须**依据它作答，不要拒答」
> v2 规则 5：「只有当参考资料**完全没有**与问题相关的内容时，才输出哨兵」

"相关"远弱于"包含答案"。问加州法规时资料里有同主题的数据合规制度 → 按规则 2 模型
**必须作答**——它是在遵守提示词，不是违规。**规则写错，兜底层再准也救不回来。**

v3 的修改：

- 规则 2 改为「只有当参考资料中**确实写明了所问的事实**时才作答」，
  并明确判据是"资料里有没有这个答案"，而不是"资料是否涉及这个话题"；
- 规则 3 列出必须输出哨兵的三种情形：话题无关、**主题相邻但未写明所问事实**
  （外部法规/他人信息/竞品数据/未来预测）、**请求本身不是知识问答**
  （写诗/翻译/改写/生成代码/闲聊/征求建议）；
- 规则 6 明确禁止"无法确认，但资料提到……"这类写法——**这正是绕过哨兵的表述**。

实测效果（52 条样本、DeepSeek）：误答率 20% → **0%**，代价是漏答率 0% → 3.1%。
那唯一一条误拒（问"核心工作时间"）经排查**不是提示词过严，而是语料缺陷**：
`attendance_policy.md` 与 `employee_handbook.md` 给出了互相矛盾的值，
模型选择拒答而不是任选一个——按 v3 规则这是正确行为。
统一两份文档的规范值（并修正考勤制度那份"核心时段跨 9 小时却称可前后一小时弹性"的
自相矛盾）后，**漏答率回到 0%**。

结论：哨兵是否生效**取决于提示词怎么界定"无法回答"**，而不取决于识别逻辑。
另外，拒答现在在引用映射之前短路，所以**拒答不会再挂引用**——
这一条从"靠兜底层清空"变成了"结构上不可能发生"。

## 补记（2026-10-08）：拒答不再是默认策略，改为「声明来源 + 通用知识」

产品侧明确要求：**知识库只是信息库，不该成为回答的闸门**。于是本 ADR 的三层拒答判定
从"主路径"退化为"兜底路径"：

| 场景 | 旧行为（v4 及更早） | 新行为（v6 + 降级开启） |
| --- | --- | --- |
| 寒暄（"你好"） | 判为非知识问答 → 拒答 | 直接友好回答，且不带引用 |
| 制度类问题、库中无资料 | 拒答 | 声明「知识库中没有…」+ 通用知识 + 禁止引用 |
| 制度类问题、库中有资料 | 依据资料 + 引用 | 不变 |
| 生成失败（模型异常） | 拒答 | **仍拒答**（用通用知识回答会掩盖真实故障） |

判据从「资料里有没有**这个答案**」放宽为「有没有**可用事实**」——因为完整答案常需
跨分节整合、且用户用词与文档用词不同（问「请假」而资料分节写「病假/事假/年假」）。
实测修复前「请假什么流程？」被判成"资料没写"而拒答，尽管检索分数高达 0.59。

**三层拒答判定本身没有删除**，`REFUSE_MARKER` / `REFUSE_TEXT` / 短句兜底都还在，
由 `ANSWER_FALLBACK_ENABLED=false` 或 `ANSWER_PROMPT_VERSION=v4` 即可回到旧行为。

### 与"无相关结果"的关系

上面的放宽带来一个副作用：**无关提问也开始走生成路径**（原先一律拒答，问题被掩盖）。
「你好」在 62 个分块里都能排到第 1（向量相似度 0.36），界面因此列出无关切片。
这暴露出本文「代价与后续」里当年预言但一直没做的那件事——
"让检索阶段产出「无相关结果」"。已在 ADR 0008 落地（标定 `min_score=0.43`）。

也就是说：**放宽回答策略的前提，是先有相关性判定**。顺序反了就会同时出现
"该答的不答"和"不该答的乱答"。若日后要回退到严格拒答，请一并回退 min_score。
